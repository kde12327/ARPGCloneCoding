# 2D 액션 RPG

패스 오브 엑자일의 아이템과 성장 구조를 참고하여 제작한 2D 액션 RPG 프로토타입입니다.

전투, 아이템, 인벤토리, 스탯, 스킬, 퀘스트와 패시브 스킬 트리 등 RPG의 주요 시스템을 직접 설계하고 구현했습니다. 기능의 개수보다는 여러 시스템이 서로 영향을 주는 구조를 구현하고, 그 과정에서 발생한 문제와 한계를 확인하는 것을 목표로 진행했습니다.

## 주요 구현 기능

### 아이템 시스템

* 베이스 아이템 데이터와 실제 생성되는 아이템 인스턴스를 구분
* 접두어와 접미어 옵션을 종류, 적용 스탯, 최솟값과 최댓값으로 구성
* CSV로 관리한 베이스 데이터를 게임에서 사용할 수 있는 형태로 변환
* 장비 사용을 통한 일부 옵션 변경 기능 구현
* 플라스크 아이템 사용 처리

### 인벤토리·창고·상점·장착 시스템

* 아이템 크기에 따른 다중 칸 인벤토리 구성
* 아이템이 차지할 영역과 다른 아이템의 충돌 여부 검사
* 배치 위치와 슬롯 타입에 따른 아이템 이동 제한
* 인벤토리, 창고, 상점 및 장비 슬롯 간 아이템 이동
* 장착 부위에 따른 아이템 장착 검사

### 스탯 및 성장 시스템

* 캐릭터의 기본 스탯과 아이템 옵션을 반영한 최종 스탯 계산
* 힘·민첩·지능의 최종값에 따라 생명력, 공격 속도, 마나 및 피해 배율 등을 다시 계산
* 스탯과 장비 효과가 변경될 때 관련 수치가 함께 갱신되는 구조 구현

### 스킬 시스템

* 메인 스킬젬과 보조 스킬젬의 연결 구조 구현
* 장착된 보조 스킬젬에 따라 메인 스킬의 효과 변경
* 스킬 사용과 공격 효과 처리
* 스킬 단축키 및 관련 UI 구현

### 패시브 스킬 트리

* 패시브 노드 선택 및 해제
* 선택하려는 노드가 기존 활성 노드와 연결되어 있는지 검사
* 노드 수가 많지 않은 프로젝트 범위를 고려하여 전체 노드를 탐색하는 방식으로 연결성 판단
* 선택한 패시브 효과를 캐릭터 스탯에 반영

### 전투 시스템

* 일반 공격과 스킬 사용
* 근접·원거리 몬스터 AI
* 캐릭터와 몬스터의 체력 및 피해 처리
* 스탯과 스킬 효과를 반영한 전투 수치 계산

### 퀘스트 시스템

* 퀘스트 조건과 보상 처리
* 이전 퀘스트의 조건을 만족하면 다음 퀘스트를 등록하는 연계 구조
* 퀘스트 데이터를 CSV로 관리할 수 있도록 구성

### 맵 시스템

* Isometric Tilemap 기반 맵 구성
* 맵을 독립된 씬으로 분리
* 웨이포인트와 포탈을 이용한 맵 이동
* 인스턴스 던전 형태의 맵 전환 구성

### UI 시스템

* 체력·마나 표시
* 스킬 단축키
* 플라스크 UI
* 인벤토리·장비·상점·퀘스트 UI

## 구현 과정에서 해결한 문제

### 베이스 아이템과 인스턴스 분리

같은 종류의 아이템이라도 생성된 옵션과 수치가 서로 달라야 했습니다. 공통 정보를 가진 베이스 아이템 데이터와 게임에서 실제로 사용하는 아이템 인스턴스를 구분하여, 하나의 베이스 데이터에서 서로 다른 옵션을 가진 아이템을 생성할 수 있도록 구성했습니다.

이 과정에서 접두어와 접미어를 옵션 종류, 적용 스탯, 값 범위로 나누어 관리했습니다. 이를 통해 아이템별 정보를 모두 별도로 작성하지 않고 공통 데이터와 개별 상태를 구분할 수 있었습니다.

### 다중 칸 아이템 배치 검사

아이템마다 차지하는 칸의 크기가 달라 단일 슬롯 방식으로는 인벤토리를 구성하기 어려웠습니다. 아이템을 배치할 시작 위치를 기준으로 점유할 모든 칸이 인벤토리 범위 안에 있는지 확인하고, 다른 아이템과 겹치는지 검사하도록 구현했습니다.

아이템 이동과 장착 과정에서도 대상 위치와 슬롯 타입을 확인하여 잘못된 위치에 배치되지 않도록 처리했습니다.

### 스탯 간 연동 처리

힘·민첩·지능과 같은 기본 스탯이 생명력, 공격 속도, 마나 및 피해 배율 등에 영향을 주도록 구현했습니다. 장비나 패시브 효과로 기본 스탯이 변경되면 관련된 최종 수치를 다시 계산하도록 구성했습니다.

다만 현재 연동 규칙 중 일부는 플레이어 초기화 코드에 직접 작성되어 있습니다. 규칙이 많아질 경우 수정 범위가 커질 수 있으므로, 다시 구현한다면 연동 규칙을 별도의 데이터나 계산 모듈로 분리할 계획입니다.

### CSV 데이터 변환 오류 확인

아이템과 퀘스트 데이터를 코드 수정 없이 관리하기 위해 CSV를 사용했습니다. CSV 데이터를 게임용 데이터로 변환하는 과정에서 필드 타입이 맞지 않아 오류가 발생했고, 오류 메시지와 대상 필드를 확인하여 데이터 타입과 변환 규칙을 수정했습니다.

CSV는 비개발자도 비교적 쉽게 수정할 수 있다는 장점이 있었지만, 입력 형식이 잘못되었을 때 오류를 사전에 확인하기 어렵다는 한계도 확인했습니다.

## 현재 상태 및 한계

이 프로젝트는 RPG 시스템 구현을 목적으로 제작한 프로토타입이며, 완성·출시된 게임은 아닙니다.

현재 확인된 주요 한계는 다음과 같습니다.

* 로그인과 캐릭터 생성 기능 미구현
* 게임 데이터 저장·불러오기 미구현
* 동일한 아이템 옵션의 중복 생성을 제한하는 처리 미구현
* 아이템 이동을 취소했을 때 원래 위치로 복구하는 처리 미구현
* 일부 보조 스킬젬 효과가 코드에 직접 연결되어 있음
* 일부 맵의 이동 불가 구간과 UI 표시 문제 존재
* 몬스터 패턴과 공격 방식이 제한적임
* 다양한 아이템·메시 환경에 대한 정량적인 성능 측정 미진행

## 배운 점

여러 RPG 시스템을 구현하면서 각 기능을 개별적으로 완성하는 것만으로는 충분하지 않다는 점을 배웠습니다. 아이템 옵션의 변경이 스탯과 스킬 계산에 영향을 주고, 장착 상태와 인벤토리 위치가 함께 관리되는 것처럼 시스템 사이의 관계를 고려해야 했습니다.

또한 기능을 빠르게 추가하기 위해 코드에 직접 작성한 규칙이 기능 확장 단계에서는 수정 범위를 넓힐 수 있다는 점을 확인했습니다. 이후 프로젝트에서는 데이터와 계산 규칙의 책임을 더 명확하게 분리하고, 저장·복구와 예외 상황을 초기 설계부터 함께 고려하고자 합니다.

## 실행 방법

1. 저장소를 복제합니다.

```bash
git clone https://github.com/kde12327/ARPGCloneCoding.git
```

2. Unity Hub에서 프로젝트 폴더를 엽니다.

3. Unity `[정확한 버전 확인 후 입력]` 버전으로 프로젝트를 실행합니다.

4. `[실제 Main 씬 경로 확인 후 입력]` 씬을 열고 Play 버튼을 누릅니다.
